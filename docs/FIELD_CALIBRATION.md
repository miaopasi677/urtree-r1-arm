# 现场标定指南（零位 / 位姿 / 夹爪 / 节拍）

> 目标：把「示意占位值」变成「你这台臂、你这个展台」的真实参数。
> 原则：**所有真机运行前必须完成本文标定**；程序用 `poses.json → calibrated` 标志强制把关。

## 0. 标定前确认

- [ ] `python r1ctl.py check` 全部关节应答正常；
- [ ] 展台清场，手机放到取件位，急停可用；
- [ ] 首次标定建议把 `demo --speed` 心里有数：所有点动命令默认按 40°/s 执行，比展示慢很多。

## 1. 零位标定（offset_deg）

**目的**：把「程序里的 0°」对齐到「这台臂的机械零位」，之后所有角度都以它为参考。

1. 上电，`python r1ctl.py teach`（程序使能并保持当前位置）；
2. 用点动把臂摆到约定的机械零位（与图纸/验收基准一致，通常接近出厂零位姿态）：
   ```
   r J2 +2        # 单关节微调（相对增量）
   j J4 -1.5      # 单关节到绝对角度
   move 0 2 0 -2 0 0 0    # 整体到位（7 个角度）
   show           # 核对各关节当前角度
   ```
3. 确认姿态正确后执行：
   ```
   zero
   ```
   程序把当前各关节角写进 `arm_config.json` 的 `offset_deg`，并把指令位姿重置为 0；
4. 验证：`show` 应显示所有关节 ≈0.0°；执行 `move 0 0 0 0 0 0 0` 臂应保持不动；
5. **重启程序**（q 退出再进），确认零位生效。

> 注意：`zero` 会改写 `arm_config.json`，改之前该文件若有手工修改请先备份。
> J2/J4 的行程边界就是 0°，`safe_margin_deg` 默认为 0，回零不会被软限位拒绝；若现场把零位定在行程内部，可把 `safe_margin_deg` 改成 1~2 更保守。

## 2. 位姿示教（poses.json）

需要标定的 7 个位姿（对应方案动作路径）：

| 名称 | 含义 | 示教要点 |
| --- | --- | --- |
| HOME | 待机/回零 | 通常即机械零位 |
| PRE_PICK | 取件预位 | 手机正上方 3~5 cm，垂直对准 |
| PICK | 取件位 | 夹爪对准手机中心，指垫略低于手机厚度一半的预估闭合量 |
| LIFT90 | 抬升展示位 | 大小臂抬起、手机离台面，观察不碰展台道具 |
| ROT_L90 | 左旋 90° | J1=-90°（以 LIFT90 为基础仅转 J1） |
| ROT_R90 | 右旋 180° | J1=+90° |
| ROT_MID | 回中 | J1=0°，同 LIFT90 |

流程（在 `teach` 会话中）：

```
move 0 90 25 -25 0 0 0      # 演示：把臂移动到目标点附近
r J3 +1 / r J3 -1           # 微调
save LIFT90 抬升展示位       # 记录当前位姿（写入 poses.json，未标定状态）
# ……逐个位姿重复……
list                        # 检查 7 个位姿是否齐全
calib LIFT90                # 逐个标记已标定（或确认无误后逐个 calib）
list                        # 应显示全部 ✓，且整体标定状态=已标定
q                           # 保存退出
```

要点：

- `save` 记录的是**当前反馈位置**，不是指令位置——等动作完全停稳再 save；
- 每个位姿标记 `calib` 前先低速走一遍 `demo --dry-run` 想象路径，重点检查 PRE_PICK→PICK 的下探轨迹不磕碰；
- 位姿文件也可以手改（JSON，`deg` 数组顺序 J1~J7，单位度），手改后记得把 `calibrated` 置 true；
- 夹爪参与取件：示教 PICK 时先用 `close`/`open` 反复试夹持位置与张合量。

## 3. 夹爪标定（q_open / q_close / kp）

夹爪闭合位置与夹持力由 `arm_config.json → gripper` 三个参数决定：
**夹持力 ≈ kp × (q_target − q_实际停住位置)**，`q_close` 越小夹得越紧。

1. `python r1ctl.py gripper-test --cycles 2`：观察开合是否顺畅、q 反馈是否正常；
2. 张开量：手机放好，逐步增大 `q_open` 直到指尖完全让开手机；
3. 闭合量：从较大的 `q_close`（如 0.10）开始，每轮改小 0.02，用真机夹手机：
   - 能夹稳、轻推不滑落 → 记下该值；
   - 夹痕明显/推不动就松 → 回退一档（或减小 `kp`）；
4. 若需要按重量区分夹持力，可开启 `grasp_tau_nm`（状态力矩 ≥ 该值即判定「已夹住」，配合 `is_grasped` 检测）；
5. 参数确认后写回 `arm_config.json`，再跑 `gripper-test` 复验。

> Dex1-1 标称夹持力 5–120 N 可调、最短闭合 0.24 s；手机夹持建议从最小有效力起步，软质夹持垫必装。

## 4. 节拍整定（speed_scale 与 duration_s）

1. 全部标定完成后：`python r1ctl.py demo --cycles 3 --speed 0.5`（半速、3 轮）；
2. 观察无磕碰、无告警后，按 0.5 → 0.8 → 1.0 逐步提到正式节拍；
3. 方案承诺单循环约 32 s：当前脚本 9 步全速合计约 35 s（含「放回手机」补充步）；若要压回 32 s，减小第 2/8 步的 `approach_s`，或评审后去掉放回步；
4. `demo --cycles 0` 连跑 30 min，看 `logs/arm_*.csv`：每步 note 与关节曲线可逐段核对节拍。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| `save` 后位姿明显不对 | save 前动作未停稳；重新走到位再 save |
| `demo` 报「位姿超出软限位」 | teach 点越界或手改越界；用 `clamp_pose` 的提示值修正 poses.json |
| 回零有异响/抖动 | 降低 `joints[].kp` 或 `max_speed_deg_s` 再试；仍抖动查机械（README 已知事项 2） |
| 夹不住手机 | `q_close` 过大或 `kp` 过小；按第 3 节逐档收紧 |
| 改了 arm_config.json 不生效 | `zero`/手改后需重启程序（配置只在启动时加载） |
